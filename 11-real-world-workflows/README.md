# 11 — Real-world workflows

## Goal
Practise a small team-style feature workflow using branches and pull requests.

## Exercises
1. Create `feature/<short-name>` from `main`.
2. Make focused commits with clear messages.
3. Push the branch and open a pull request.
4. Review the diff as if you were a teammate.
5. Respond to one review comment with a follow-up commit.
6. Merge the pull request using the repository's chosen merge strategy.
7. Delete the feature branch and update your local `main`.

## Pull request checklist
- [ ] The title explains the change.
- [ ] The description explains why the change is needed.
- [ ] The diff contains only related changes.
- [ ] Tests or manual verification are described.
- [ ] No secrets or generated files are committed.

## Reflection
Which merge strategy did you use, and why?
